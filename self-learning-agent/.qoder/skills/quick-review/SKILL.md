# 学习文件夹快速复习

## 目标

对 `self-learning-agent/`（或 `learning-notes/`）下的一个学习子项目（如 memory-test、rag-test、milvus-test、tool-test），生成并维护一份 `REVIEW.md`，让用户能在 10-15 分钟内完成一次高质量复习；也可以按该文件反向出题抽问用户。

## 工作流程

### 第 1 步：扫描文件夹（并行读取）

按优先级收集材料，尽量并行：

1. `README.md` — 学习目标、已完成项、演进路线（里面通常有用户自己写的核心结论，必读）
2. `package.json` — scripts（怎么运行）、dependencies（技术栈）
3. `src/` 下全部源码（`find <dir>/src -type f` 列出，逐个 Read；若文件很多，优先带大段中文注释的示例脚本）
4. `knowledge-graph/graph.md` + `graph.json` — 用户维护的知识图谱，是节点/概念/边关系的现成素材；graph.md 末尾常有"持久化版 vs 内存版"这类对比表，直接可复用
5. `.env.example`（如有）— 环境变量

### 第 2 步：分析代码

对每个脚本提炼：
- **学习目标**（脚本头部注释通常已写明）
- **核心 API**（import 了什么、new 了什么、调了什么方法链）
- **流程步骤**（分几步、顺序如何、哪步是关键）
- **横向对比**（同一主题的多个脚本之间：v1 vs v2、内存版 vs 持久化版、localhost vs remote 的差异点）
- **踩坑**（注释里的"注意/坑/为什么不这么写"段落，通常是用户亲身踩过的，复习价值最高）
- **运行方式与前置条件**（是否需要 API Key、外部服务如 Milvus/Redis、产出什么文件）

### 第 3 步：生成 REVIEW.md

写到目标文件夹根目录：`<目标文件夹>/REVIEW.md`。若已存在则先读旧版，合并更新（保留用户手动添加的内容，更新过时部分）。

**必须包含以下章节**（顺序固定）：

1. **一图流 / 一句话总结** — 本主题的本质，用一个 ASCII 图或一句话说透
2. **核心速查表** — 关键概念、类型、参数的表格（行数宁少勿多，每行必须值得背）
3. **必背流程** — 代码步骤化（每步一行代码 + 一句注释），标注哪步最关键、哪步漏了会出什么 bug
4. **横向对比表** — 同主题多实现的差异（内存 vs 文件、v1 vs v2 等），差异点用 ★ 或加粗突出
5. **踩坑速查表** — 编号列出，格式：`坑 → 正解`，覆盖：文件名/命令易错点、异步漏 await、并发问题、异常分类
6. **运行速查** — 一段 bash 块：安装、运行每个脚本、清理；标注哪些脚本不需要 API Key、哪些需要外部服务
7. **延伸知识点（联想区）** — 基于已学内容向外联想 5-8 个进阶方向，每个给一句话解释 + 与本项目哪个概念对应。这是用户明确要求"根据 agent 知识联想后续知识点"的部分，要给出生态级的全貌（框架的下一代 API、第三方替代品、工程化议题、评估方法）
8. **自测清单** — 10 道左右问答式题目，括号里附答案提示；题目按"必背 → 对比 → 延伸"排序

**写作要求**：
- 全文中文，代码/类名/API 保持英文原文
- 表格优先于段落；每条信息可独立成立（复习时随机翻到任何一页都有用）
- 引用具体文件和类名时给路径，如 `src/history-test2.mjs:98`
- 不复制大段源码进复习文件；只留"步骤骨架 + 关键行"
- 长度参考：150-300 行。超过说明在抄代码而不是提炼

### 第 4 步：向用户汇报

完成后输出简短总结：REVIEW.md 的绝对路径、覆盖了哪些脚本、延伸区联想了哪些方向，并提示可以随时说"抽考我 <文件夹>"进入提问模式（见下）。

## 抽考模式（可选触发）

用户说"抽考我"、"考考我 <文件夹>"时：
1. 读该文件夹的 REVIEW.md 自测清单（第 8 节）
2. 一次出一题，等用户口头回答后再对照答案给出评判（答对/答错/部分正确 + 补充）
3. 答错的题标记下来，连续 3 题后给一次错误汇总
4. 不改 REVIEW.md，除非用户暴露出复习文件没覆盖的知识盲点——此时把它补进自测清单

## 边界与约束

- 只读分析 + 写入目标文件夹的 REVIEW.md；不修改任何源码、README、graph 文件
- 如果文件夹没有 knowledge-graph，跳过第 1.4 项即可
- 如果脚本依赖外部服务（Milvus、Redis 等），在"运行速查"标注前置条件，但不要替用户启动这些服务
- 每次复习同一文件夹时，先 diff 源码与旧 REVIEW.md 的时间/内容，只更新变化部分，重写全文会丢失用户的手动批注
- REVIEW.md 中不发明仓库里不存在的 API；引用的类名、命令必须在源码或 package.json 中出现过
